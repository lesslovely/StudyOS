## 阶段目标

用浏览器原生能力（HTML + CSS + JavaScript + localStorage）做出 StudyOS 第一个可运行版本，**完整跑通核心学习闭环**，并让开发者亲手掌握 Web 应用最底层的结构、表现、行为、状态与持久化。

```text
创建知识 → 设置掌握度 → 查看知识状态 → 发现薄弱知识
→ 创建关联任务 → 完成任务 → 产生学习记录
→ 更新掌握度 → 得到下一步建议 ↺
```

闭环的权威表述见 [总路线#核心学习闭环](../roadmap.md#核心学习闭环)。本阶段“AI 分析 / 建议”环节由**规则引擎**承担（[D-008](../decisions.md)）。

## 前置条件

- Phase 0 已完成：定位、闭环、边界明确（✅）。
- 仓库仅有空脚手架（`src/index.html`、`src/css`、`src/js`），无任何依赖。
- 开发者具备基础学习意愿，不要求预先掌握 JavaScript；本阶段就是学习 JavaScript 的载体。

## 功能范围（做什么）

### 1. Knowledge 知识

- 创建、查看、修改、删除知识节点。
- 轻量层级：每个知识节点属于一个领域（domain），通过 parent 形成树（如 `JavaScript / 函数 / 闭包`）。
- 简单关系：`related`（互相关联）、`prerequisite`（前置知识）；层级用 parent 表达，不与关系混淆。
- 不做复杂知识图谱（[D-009](../decisions.md)）。

### 2. Knowledge Detail 知识详情

- 基本信息：名称、所属领域、层级位置、描述。
- 知识内容（Content）：定义、我的理解、示例 / 代码示例、使用场景、常见错误、疑问、学习资料。
- 用户状态（UserState）：掌握度 1~100（自评）、重点标记、当前学习状态。
- 关系区：父级 / 子级、相关知识、前置知识，可点击跳转。
- 学习数据区：关联任务列表、该知识的学习记录时间线。

### 3. Task 任务

- 创建、查看、完成（删除能力可后置或最小提供）。
- **创建任务必须关联一个知识节点**；不允许存在与知识无关的任务（Task 是手段，不是 Todo）。
- 完成任务时自动产生一条 Learning Record，并进入掌握度更新流程。

### 4. Learning Record 学习记录

- 自动记录：任务完成、自评调整掌握度。
- 字段：时间、行为、关联知识、结果、掌握度变化（before → after）。
- 可按知识查看、可在总览按时间查看。

### 5. Recommendation 规则建议（AI 雏形）

- 纯函数规则引擎，输入知识状态，输出建议与理由：
  - 掌握度 < 40 → 建议重新学习；
  - 40~70 → 建议练习；
  - 70 以上 → 建议复习 / 综合应用。
- 补充规则：被标记重点且掌握度低的知识优先；存在未掌握前置知识时给出提示。
- 建议只负责“推荐 + 理由 + 一键创建任务入口”，**采纳与否由用户决定**（Advisor 交互雏形）。

### 6. Persistence 持久化

- localStorage 保存全部数据，刷新 / 重开浏览器后恢复。
- 数据带 schema 版本号，体验最基础的版本迁移意识。

## 不做什么（范围边界）

React / Vue / TypeScript、npm 与构建工具、Node.js、后端、数据库、账号认证、真实 AI API、AI Agent、云部署、复杂知识图谱、向量数据库、RAG、多用户、权限、高级分析、间隔重复、高级测评、复杂状态管理库、UI 组件库、前端路由库。

原因统一记录在 [技术路线](../architecture-roadmap.md#phase-1-架构基线) 与 [D-003](../decisions.md)：本阶段的目的是理解应用本质，任何提前引入的框架都会遮蔽学习目标。

## 数据模型（规划级，不是代码）

Phase 1 即按四组分离**分组建模**，但物理上存在同一对象 / 同一存储键中，不提前拆表（为 P4 演进留路，见[数据模型演进](../architecture-roadmap.md#数据模型演进)）。

### KnowledgeNode 知识节点

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| 基本信息 | id、title、domain、parentId、description | parentId 为空表示领域根 |
| Content 内容 | definition、myUnderstanding、examples、useCases、commonMistakes、questions、references | 文本字段，允许为空，随学习逐步补充 |
| UserState 状态 | mastery（1~100 自评）、starred（重点，布尔）、status（建议枚举：未学习 / 学习中 / 复习中 / 已掌握） | mastery 与 starred 相互独立（[D-007](../decisions.md)） |
| Relations 关系 | 不内嵌，单独存储：{ sourceId, targetId, type: related \| prerequisite } | parent 由 parentId 表达；related 双向展示 |
| Learning Data | taskIds、recordIds（衍生引用，可由任务 / 记录反查） | 不在知识对象里冗余业务数据 |
| 元信息 | createdAt、updatedAt | — |

### Task 任务

| 字段 | 说明 |
| --- | --- |
| id、title、note | title 必填 |
| knowledgeId | **必填**，关联唯一知识节点 |
| status | todo / done |
| createdAt、completedAt | 完成时写 completedAt |

### LearningRecord 学习记录

| 字段 | 说明 |
| --- | --- |
| id、timestamp | 发生时间 |
| knowledgeId | 关联知识（必填） |
| taskId | 来源任务，可空（自评等手动行为为空） |
| behavior | 行为类型：完成任务 / 学习 / 练习 / 自评 / 复习 |
| result | 结果备注，可空 |
| masteryBefore、masteryAfter | 掌握度变化，允许相等 |

### Recommendation 建议

不持久化或仅做轻量持久化；由规则引擎实时计算，结构为：{ knowledgeId, level, reason, suggestedAction }。它是未来 AI 服务层的**接缝**，内部实现 P8 可整体替换，交互不变。

### 存储键（概念级）

`studyos:knowledge`、`studyos:relations`、`studyos:tasks`、`studyos:records`、`studyos:meta`（含 schema version）。所有读写必须经过统一的 store 职责模块，视图不直接访问 localStorage（存储接缝）。

## 页面规划（视图级，不做路由库）

通过简单的视图切换实现，建议三个视图（已确认推迟到 M2/M3 进入时拍板，见 [decisions.md 待确认问题处理结果](../decisions.md#待确认问题处理结果2026-09-19)）：

1. **知识总览**：领域 / 知识树浏览；薄弱知识列表（mastery < 40 或重点未掌握）；规则建议区；待办任务；最近学习记录。它是旧 Dashboard 的收敛形态，只服务闭环。
2. **知识详情**：上述 Knowledge Detail 的全部内容；内联自评掌握度、标记重点、创建关联任务、查看记录时间线、跳转关系知识。
3. **任务与记录**：任务清单（按知识分组）、完成操作；学习记录时间线。若信息量小，可并入总览与详情，进入阶段时按学习负担决定。

知识创建 / 编辑使用简单表单页或表单区域（不引入弹窗库）。

## 验证标准

### 端到端闭环走查（必须全程由开发者独立操作并解释）

1. 创建知识 `闭包`（挂在 `JavaScript / 函数` 下），补充定义与理解；
2. 设置掌握度为 30，标记重点；
3. 在总览看到它出现在薄弱知识区；
4. 基于建议创建任务“完成 3 道闭包代码题”，确认任务关联到 `闭包`；
5. 完成任务，系统生成学习记录；
6. 将掌握度更新为 65，记录显示 `30 → 65`（含任务带来的变化）；
7. 规则建议从“重新学习”变为“练习”；
8. 刷新浏览器，全部数据与状态仍在；
9. 建立 `闭包` 与 `作用域链` 的 related 关系，详情页可互相跳转。

### 四类验收

- **功能验收**：上述走查全程可用；知识 / 任务 / 记录的增删改查行为正确；空数据有引导而非报错。
- **技术验收**：语义化结构、事件绑定、DOM 更新、数据与 UI 同步关系正确；存储只经 store 层；规则引擎是独立纯函数；无不安全的 HTML 拼接（XSS 基础意识）。
- **知识验收**：能讲清“点击事件 → 数据变化 → 重新渲染 → localStorage”的完整链路；能解释 JSON 序列化、掌握度与重点的区别、层级与关系的区别、规则引擎为何是 AI 接缝。
- **工程验收**：js 文件按职责划分、命名清晰、无大段重复；手动验证清单全部通过；每个里程碑一个表达清晰的提交；未引入禁止清单中的任何技术。

## Git 节点与 Review 机制

- Phase 1 开发在 `feature/knowledge` 分支小步提交（[D-013](../decisions.md)；M0 基线已在 main 上）；一个里程碑至少一个提交，提交信息形如 `phase-1: knowledge crud with hierarchy`。
- 每个里程碑执行 Review 门：开发者自述实现 → AI 针对原理提问 → AI Review diff 并指出问题 → **开发者自己修复** → 跑验证清单 → 进入下一里程碑。
- AI 不直接替开发者写当阶段正在学习的代码；如破例，必须在复盘里记录原因与学习影响（原则见[学习路线](../learning-roadmap.md#学习方法论)）。

## 风险与反模式（本阶段重点防范）

- 把任务做成普通 Todo（忘记挂知识）——功能验收直接不通过。
- 过早抽象 / 过早拆文件框架——保持初学者能通读每个文件。
- 追求视觉效果挤占原理学习——样式够用、整洁即可。
- 规则引擎硬编码在视图代码里——会堵死 P8 的 AI 接缝。
- 数据模型扁平到无法演进——Content / UserState 必须分组。
- 计划过细焦虑——日级任务等进入阶段后在 `plan.md` 中展开。
