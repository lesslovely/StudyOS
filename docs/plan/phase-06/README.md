## 阶段定位

建立用户身份、认证、授权与个人数据隔离。StudyOS 的知识与学习数据高度个人化，系统必须知道“这是谁的数据”，并保证用户只能访问自己的数据。

## 前置条件

- Phase 5 全栈闭环稳定；数据库表已预留归属扩展位置。
- 开发者理解后端分层与基础安全意识（P3 起接触的配置 / 校验习惯）。

## 目标矩阵

| 维度 | 内容 |
| --- | --- |
| 产品目标 | 注册、登录、登出；登录后的个人学习空间；账户设置最小集 |
| 用户价值 | 数据有明确归属，换设备登录后仍只看到自己的知识体系 |
| 技术目标 | 注册 / 登录 / 登出流程、认证与授权的区别、Session 或 Token 原理（进入阶段选型并记录）、密码哈希存储、数据按归属过滤、常见认证风险 |
| 学习目标 | 见 [学习路线#Phase 6](../learning-roadmap.md) |
| 实践方式 | 先画“未登录 / 已登录 / 越权访问”三种场景的行为表，再实现 |
| 验证方式 | 手工构造越权请求被正确拒绝；能解释凭证在浏览器与服务器之间如何流转 |
| 阶段产出 | 能安全区分用户、个人数据隔离的 StudyOS 版本 |

## 功能范围

**做什么**：

- 用户账户（注册、登录、登出）与登录状态保持；
- 所有业务表加归属（owner），所有查询 / 修改强制归属校验；
- 未登录访问的统一处理；个人空间与最小账户设置；
- 密码使用成熟哈希方案存储，不自行发明加密；
- 认证失败、凭证过期、越权访问的明确错误反馈与日志。

**不做什么**：复杂角色 / 组织权限、单点登录、OAuth 第三方登录（可作 Horizon）、企业级身份平台、多用户协作（StudyOS 坚持个人定位）。

## 架构要点

- 认证逻辑集中在中间件 / 依赖层，业务代码默认拿当前用户，不允许各接口自行解析凭证。
- 授权校验在服务端，绝不依赖“前端不显示按钮”作为安全边界。
- 密钥、凭证签名材料走环境变量；日志中不出现密码与完整凭证。
- 为 P8 AI、P9 RAG 预留原则：所有智能能力同样只能访问当前用户的数据。

## 验证标准

- **功能验收**：能注册、登录、登出；两个用户的数据严格互不可见。
- **技术验收**：密码哈希存储、凭证校验、归属过滤、越权拒绝均正确；会话过期有处理。
- **知识验收**：能讲清认证 vs 授权、Session vs Token 的取舍、密码安全基本点。
- **工程验收**：敏感信息不入库不入日志；异常登录与越权有日志、有反馈。

## 主要风险

- 只在前端隐藏操作造成假安全——服务端授权测试为硬性验收。
- 自研密码 / 令牌方案——明确禁止，使用成熟库。
- 加认证时遗漏个别查询接口——逐端点建立归属校验清单。
