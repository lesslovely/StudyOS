## 阶段定位

让 AI 在**明确权限与确认机制**下调用 StudyOS 的工具，完成多步骤学习辅助工作流：查询学习状态、分析薄弱点、制定计划，并在用户确认后创建 / 更新任务。这是“Agentic Learning System”的起点，但 Agent 永远不获得无限制权限，也绝不绕过用户决定权（Advisor 原则的延伸：**读操作可自主，写操作必确认**）。

## 前置条件

- Phase 8 提案交互成熟（用户已习惯接受 / 修改 / 拒绝）。
- Phase 9 可检索个人知识；业务 API（P3–P7）边界清晰、可被安全包装为工具。
- 认证与数据隔离可靠，审计意识已建立。

## 功能范围

**做什么**：

- 只读工具：查询知识状态、任务、记录、测评、检索个人知识（P9）；
- 写工具（逐个开放）：创建任务、更新任务状态、调整计划——每步写操作生成待确认提案；
- 工作流示例：分析薄弱点 → 提出学习计划（一组任务）→ 用户审批 → 批量创建任务；
- 工具参数严格校验；执行结果回传给模型做自我验证；
- 审计日志：谁（哪个用户）、何时、哪个 Agent、调用了什么、确认结果如何。

**不做什么**：无人值守自动执行、无限制数据库 / Shell / 系统权限、自主修改知识内容而不确认、多 Agent 自治系统、自动发邮件 / 对外操作、长期后台运行 Agent。

## 架构要点

- 工具注册表：每个工具有明确名称、参数 schema、读写级别、所需权限；默认全部只读，写工具显式声明。
- **确认门（Confirmation Gate）**：任何写操作在执行前暂停，向用户展示意图、参数与影响，获批后才执行；批量计划可一次审批但逐项可见。
- 副作用控制：写操作走现有业务 API 与校验，不为 Agent 另开后门；关键操作可回滚。
- 可观测性：记录模型决策、工具选择、参数、结果与失败；失败时给出人工接管路径。
- 边界：Agent 不能自行扩大权限、不能调用未注册工具、不能访问他人数据。

## 验证标准

- **功能验收**：只读分析正确；“分析 → 计划 → 审批 → 创建任务”工作流端到端跑通。
- **技术验收**：参数校验、权限分级、确认门、失败重试 / 恢复、日志齐全；越权与未确认写操作在测试中无法发生。
- **知识验收**：能讲清 Agent 与普通问答 / RAG 的区别、工具调用循环、为何必须有人在回路中。
- **工程验收**：关键操作可审计、可回滚；系统不盲信模型输出；构造工具误用时能安全中止。

## 主要风险

- 权限放开过快——按“只读 → 单写 → 多步”三步开放，每步验收后再走下一步。
- Agent 静默改数据——确认门与审计是硬性门禁，不接受例外。
- 工作流无限循环 / 失控——步数上限、超时与人工中止。
- 过早追逐复杂框架——先用最直接的工具调用实现一个工作流，再谈编排框架。
