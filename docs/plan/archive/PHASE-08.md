# Phase 8 — Embedding + Vector Database + RAG

## 阶段目标

建立个人知识库检索能力，让 AI 回答问题时能够基于 StudyOS 中的相关学习内容。

## 为什么学习

仅依赖模型已有知识或当前上下文，无法可靠回答个人学习历史。RAG 将个人资料转换为可检索内容，再把相关信息交给模型。

## 核心知识

- 文档与知识片段
- 文本切分和元数据
- Embedding 与相似度
- 向量数据库的基本概念
- 检索、重排和上下文组装
- RAG 的准确性、引用和评估

## 核心功能

- 保存和管理个人学习资料
- 将记录或 Markdown 内容纳入知识库
- 检索历史学习内容
- 基于个人知识回答问题
- 辅助发现已掌握内容和知识缺口

## 技术范围

引入 Embedding、向量存储和 RAG。具体模型、向量数据库及检索方案在本阶段根据数据规模和实际效果选择。暂不提前锁定厂商，也不直接进入 Agent。

## 阶段产出

一个能够检索个人学习知识并把相关依据用于 AI 辅助的知识库能力。

## 验收方向

### 功能验收

资料能够进入知识库，问题能够返回相关内容和可理解的回答。

### 技术验收

切分、索引、检索、上下文限制和更新机制基本合理。

### 知识验收

能解释 Embedding、向量相似度、检索和生成之间的关系。

### 工程验收

知识来源、权限、更新和错误结果具有可追踪性。

## 与下一阶段的关系

RAG 让系统能够回答问题，但如果希望系统查询业务数据、制定计划或更新任务，就需要受控地调用应用工具，因此进入 Agent。
