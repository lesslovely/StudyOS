# Phase 3 — HTTP + FastAPI + REST API

## 阶段目标

建立后端服务，理解浏览器、HTTP 请求、API 和服务器之间的数据流。

## 为什么学习

本地存储无法满足跨设备访问、集中处理和未来用户数据管理。前端需要通过明确的网络协议与后端交换数据。

## 核心知识

- HTTP 请求、响应、方法、状态码和请求体
- JSON 与 API 契约
- REST 资源设计
- Python Web 服务基础
- FastAPI 路由、参数、校验和错误处理
- 跨域、环境配置和基础安全意识

## 核心功能

- 为学习记录、任务和项目规划 API
- 将主要读写流程迁移到后端服务
- 让前端通过 HTTP 获取和修改数据
- 建立基础错误反馈

## 技术范围

使用 Python、FastAPI、HTTP 和 REST API。数据可以暂时使用简单的服务端临时存储。暂不锁定数据库和部署方案。

## 阶段产出

一个能被前端调用、具有清晰资源边界和基础校验的 StudyOS 后端原型。

## 验收方向

### 功能验收

前端能够通过 API 读取和修改核心资源。

### 技术验收

请求、响应、状态码、参数校验和错误处理符合基本约定。

### 知识验收

能解释浏览器为何需要 API、HTTP 如何传输数据以及前后端边界。

### 工程验收

API 命名和职责清楚，前后端错误不会被静默吞掉。

## 与下一阶段的关系

服务端临时数据无法可靠持久化，也难以表达记录、任务和项目之间的关系，因此需要 SQL、PostgreSQL 和 ORM。
