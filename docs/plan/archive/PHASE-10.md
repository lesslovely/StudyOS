# Phase 10 — 测试、工程化与 Git

## 阶段目标

建立与当前系统规模匹配的测试、版本管理、代码质量和持续改进能力。

## 为什么学习

当 StudyOS 同时包含前端、后端、数据库和 AI 工作流时，仅靠手动验证无法可靠发现回归。工程化让学习成果能够稳定演进。

## 核心知识

- 单元测试、集成测试和端到端测试
- API、数据层和前端行为测试
- 测试替身与 AI 调用测试策略
- Git 分支、提交、Review 和历史管理
- 静态检查、格式化和持续验证
- 缺陷记录、日志和可观测性

## 核心功能

- 为核心业务建立自动化测试
- 验证认证、数据隔离、AI 边界和工具权限
- 建立清晰的 Git 提交和 Review 习惯
- 形成可重复的验证流程

## 技术范围

引入适合项目规模的测试工具和工程检查。具体框架在进入阶段时选择。暂不为了追求覆盖率而制造无价值测试，也不提前建立复杂 CI 平台。

## 阶段产出

一个有测试保护、提交清晰、问题可追踪、能够安全修改的 StudyOS 代码库。

## 验收方向

### 功能验收

核心功能和关键失败场景有可重复验证方式。

### 技术验收

测试层次合理，测试结果可信，工程检查能够发现常见问题。

### 知识验收

能解释不同测试类型的目的、边界和取舍。

### 工程验收

提交表达清楚变更，Review 有依据，回归问题可定位。

## 与下一阶段的关系

应用的运行组件增多，开发环境一致性和交付方式成为问题，因此需要容器化。
