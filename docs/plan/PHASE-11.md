# Phase 11 — Docker 与容器化

## 阶段目标

用容器建立更一致、可重复的开发和运行环境，为部署做准备。

## 为什么学习

前端、后端、数据库和相关服务的环境差异会增加启动和交付成本。容器化可以明确运行依赖，但只有在系统确实需要多服务协作时才引入。

## 核心知识

- 镜像、容器和层
- Dockerfile 与构建过程
- 多服务编排
- 网络、卷和数据持久化
- 环境变量与配置边界
- 镜像安全和资源管理

## 核心功能

- 统一运行 StudyOS 所需服务
- 建立可重复的本地开发环境
- 管理服务之间的连接
- 为测试和部署提供一致基础

## 技术范围

使用 Docker 及适合项目规模的容器编排方式。具体镜像和部署结构不提前固定。暂不引入 Kubernetes 或复杂平台工程。

## 阶段产出

能够以一致方式启动、停止、更新和诊断 StudyOS 运行环境。

## 验收方向

### 功能验收

主要服务能在容器环境中协同运行，数据持久化行为明确。

### 技术验收

构建、网络、卷、配置和服务依赖理解正确。

### 知识验收

能解释容器与虚拟机的区别，以及镜像、容器和卷的作用。

### 工程验收

环境配置不泄露敏感信息，运行方式有文档且可复现。

## 与下一阶段的关系

容器解决运行封装，但真实交付还需要理解 Linux 主机、反向代理、HTTPS、域名和运维，因此进入部署阶段。
