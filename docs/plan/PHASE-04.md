# Phase 4 — SQL + PostgreSQL + ORM

## 阶段目标

设计并使用可靠的关系型数据模型，让 StudyOS 的核心数据能够持久化、查询和维护。

## 为什么学习

随着记录、任务和项目数量增长，临时存储无法满足一致性、检索、约束和长期维护需求。关系型数据库能把数据结构和业务关系明确下来。

## 核心知识

- 关系型数据库和 SQL
- 表、字段、主键、外键和约束
- 查询、筛选、排序、分页和关联
- PostgreSQL 基础
- ORM、模型映射和迁移
- 事务、一致性和基础索引意识

## 核心功能

- 持久化学习记录、任务和项目
- 支持核心资源的查询、更新和删除
- 建立资源之间必要的关系
- 处理基础数据校验和一致性

## 技术范围

使用 SQL、PostgreSQL 和 ORM。具体 ORM、版本和运行方式在进入本阶段时根据需求决定。暂不引入复杂缓存、分布式数据库或微服务。

## 阶段产出

一个具有明确数据模型和持久化能力的后端数据层。

## 验收方向

### 功能验收

核心数据重启后仍存在，并能正确增删改查。

### 技术验收

表结构、关系、约束、查询和迁移逻辑合理。

### 知识验收

能解释 SQL 与 ORM 的关系、事务意义及数据库与 localStorage 的区别。

### 工程验收

数据模型可演进，敏感配置不硬编码，错误和边界情况可追踪。

## 与下一阶段的关系

数据库具备持久化能力后，需要让 React 前端与 API、数据库形成稳定的完整闭环，因此进入前后端集成。
