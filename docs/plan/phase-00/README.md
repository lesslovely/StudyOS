## 阶段定位

明确 StudyOS 的产品定位、长期愿景、学习目标、阶段边界与项目驱动学习方式，并建立一套可以长期维护、持续更新的计划系统。本阶段不写任何业务代码。

## 为什么先做这个

任何后续技术都应服务于清晰的问题。先定义“解决什么、不做什么、按什么顺序演进”，可以避免过早工程化、无目的囤技术，以及计划互相矛盾。2026-09-17 的整合把最初一次性写成的大计划升级为分层、可追溯、可维护的 Plan Network，背景见 [D-001](../decisions.md)。

## 范围边界

- 做：规划文档、双向链接、状态图例、维护流程、旧计划整合归档。
- 不做：实现代码、初始化技术栈、安装依赖、建前后端 / 数据库 / 部署环境。
