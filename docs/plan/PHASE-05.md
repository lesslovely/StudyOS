# Phase 5 — 前后端完整集成

## 阶段目标

把前端、API 和数据库连接成一个可持续使用的基础全栈应用。

## 为什么学习

前几个阶段分别建立了界面、服务和数据层，下一步必须验证它们在真实数据流中的协作，而不是继续孤立学习技术。

## 核心知识

- 前后端数据流
- API 客户端与异步状态
- 加载、空数据和错误状态
- 表单校验与数据转换
- 接口契约和版本意识
- 基础日志与问题定位

## 核心功能

- Dashboard 读取真实汇总数据
- 学习记录、任务和项目的完整流程
- 跨页面数据同步
- 数据筛选、排序或基础统计
- 本地 MVP 向服务端数据的平稳迁移

## 技术范围

使用 React、TypeScript、FastAPI、REST API、PostgreSQL 和 ORM。暂不引入微服务、复杂缓存或复杂状态框架，除非真实需求证明必要。

## 阶段产出

一个前后端分离、数据可持久化、能够长期使用的 StudyOS 基础版本。

## 验收方向

### 功能验收

核心用户流程从界面到数据库完整可用。

### 技术验收

异步请求、错误处理、数据校验和边界状态合理。

### 知识验收

能追踪一次操作从 UI 到 API 再到数据库并返回的全过程。

### 工程验收

前后端职责清晰，接口变更可沟通，问题能够定位到正确层次。

## 与下一阶段的关系

当数据真正持久化后，需要区分不同使用者并保护个人学习内容，因此自然进入认证和用户系统。
