# StudyOS 学习路线图（Learning Roadmap）

> 层级：Level 1 的学习视角。回答“开发者在每个 Phase 学什么、在哪里实践、如何证明学会、留下什么”。
> 总路线见 [roadmap.md](roadmap.md)，产品目标见 [product-roadmap.md](product-roadmap.md)，技术架构见 [architecture-roadmap.md](architecture-roadmap.md)。

## 学习方法论

- **项目驱动**：`项目需求 → 发现问题 → 学习对应知识 → 应用到项目 → 测试与验证 → 继续迭代`，不先囤完知识再做项目。
- **理解优先**：开发者必须能讲清自己写出的每一部分；默认工作流是 `理解 → 规划 → 用户实现 → AI 解释/Review → 用户修复 → 验证 → 下一步`。
- **功能完成 ≠ 学习完成**：每个阶段必须同时通过功能、技术、知识、Debug、工程五类验收。
- **AI 的学习角色**：Product Advisor、Architecture Advisor、Teacher、Code Reviewer、Debug Assistant、Research Assistant；**不是全自动代写者**。若某阶段需要 AI 直接实现大量代码，必须在该 Phase 文档中说明原因以及对学习目标的影响。

## 五条学习主线

```text
Web 前端线：HTML/CSS → JavaScript/DOM/Event → 模块化 → React → TypeScript → Vite
后端协议线：HTTP/REST → Python → FastAPI → 认证授权 → 服务端校验与错误处理
数据  线：本地对象建模 → JSON/localStorage → SQL → PostgreSQL → ORM/迁移 → 向量检索
AI   线：规则建议(P1) → Prompt/LLM(P8) → RAG(P9) → Tool Calling/Agent(P10)
工程  线：Git(P1 起) → 调试与手动验证(P1 起) → 自动化测试(P11 体系化) → Docker → Linux/部署
```

## 分阶段学习计划

每个 Phase 同时回答六件事：**产品能力 / 用户价值 / 学什么 / 在哪实践 / 如何验证学会 / 阶段产出**。

### [Phase 1](phase-01/README.md) — Web 基础与原生 JavaScript

- **产品能力**：知识学习闭环 MVP 离线可用。**用户价值**：第一次拥有带状态的个人知识系统。
- **学什么**：语义化 HTML 与表单、CSS 布局与响应式、JavaScript 语法核心、DOM、Event、对象与数组数据建模、状态与 UI 同步、localStorage 与 JSON、基础模块化、调试、Git 基础提交。
- **在哪实践**：Knowledge CRUD、知识树、详情页、关联任务、学习记录、规则建议每个功能都由开发者手写。
- **如何验证**：能独立讲清“一次点击如何改变数据、数据如何改变 DOM、刷新后数据为何还在”；完成端到端闭环走查。
- **产出**：可运行 MVP + 手动验证清单 + 清晰的 Git 提交历史。

### [Phase 2](phase-02/README.md) — 前端工程化

- **学什么**：React 组件 / props / state、表单与条件渲染、组件组合与数据流、TypeScript 类型 / 接口 / 泛型基础、Vite 构建、npm 与模块化。
- **在哪实践**：把 P1 的知识闭环用组件化方式重建，类型定义直接映射知识数据模型。
- **如何验证**：能解释声明式 UI 与命令式 DOM 操作的区别、类型系统抓住了哪类错误；P1 功能在新前端中全部保持可用。
- **产出**：组件化、类型化的 StudyOS 前端。

### [Phase 3](phase-03/README.md) — HTTP 与后端入门

- **学什么**：HTTP 请求 / 响应 / 方法 / 状态码、JSON 与 API 契约、REST 资源设计、Python 基础、FastAPI 路由 / 参数 / 校验 / 错误处理、跨域与配置。
- **在哪实践**：为知识、任务、学习记录设计并实现资源 API（临时存储）。
- **如何验证**：能追踪一次请求从浏览器到路由处理再到响应的全过程；能解释前后端边界。
- **产出**：前端可调用的后端原型。

### [Phase 4](phase-04/README.md) — 数据库与数据建模

- **学什么**：关系模型与 SQL、主键 / 外键 / 约束、查询 / 筛选 / 排序 / 分页 / 关联、PostgreSQL、ORM 与模型映射、迁移、事务与索引意识。
- **在哪实践**：把 P1 就分组设计的知识模型落成表：知识内容 / 用户状态 / 层级关系 / 任务 / 记录。
- **如何验证**：数据重启后存在、关系查询正确；能讲清事务意义与数据库相对 localStorage 的本质区别。
- **产出**：可演进的持久化数据层。

### [Phase 5](phase-05/README.md) — 全栈集成

- **学什么**：API 客户端、异步状态、加载 / 空 / 错误三态、表单校验与数据转换、接口契约与版本意识、日志与问题定位。
- **在哪实践**：闭环从 UI → API → 数据库完整打通，本地数据迁移到服务端。
- **如何验证**：能独立追踪一次“完成任务 → 掌握度更新”操作穿越三层的全过程。
- **产出**：可长期使用的基础全栈版。

### [Phase 6](phase-06/README.md) — 认证与安全基础

- **学什么**：注册 / 登录 / 登出、认证与授权的区别、Session/Token 原理、密码哈希与存储安全、数据归属与隔离、常见认证风险。
- **在哪实践**：用户体系与按用户隔离的知识数据。
- **如何验证**：能解释认证与授权、会话与密码安全的区别；越权访问测试被正确拒绝。
- **产出**：安全区分用户的 StudyOS。

### [Phase 7](phase-07/README.md) — 测评建模与规则引擎

- **学什么**：题库 / 试卷 / 作答的数据建模、单知识与综合测评组卷逻辑、评分规则、掌握度多信号聚合、基础统计。
- **在哪实践**：围绕知识关系（如闭包 → 作用域链）实现综合测试，结果回写掌握度。
- **如何验证**：能解释测评结果如何改变掌握度、为何聚合规则这样设计；测评 → 记录 → 建议链路跑通。
- **产出**：测评系统与多信号掌握度。

### [Phase 8](phase-08/README.md) — LLM 应用工程

- **学什么**：LLM API 交互、Prompt 与上下文组织、结构化输出与校验、重试 / 超时 / 速率 / 成本、隐私与幻觉认知、AI 效果评估、Advisor 交互设计。
- **在哪实践**：AI 分析薄弱点、生成建议与理由、出题、复盘；全部以提案形式等待用户决定。
- **如何验证**：能讲清模型输入输出、幻觉、结构化校验与成本边界；AI 失败时系统可降级。
- **产出**：可解释、可拒绝的 AI 建议层。

### [Phase 9](phase-09/README.md) — 检索与 RAG

- **学什么**：文档切分与元数据、Embedding 与相似度、向量库、检索 / 重排 / 上下文组装、RAG 准确性与引用、RAG 评估。
- **在哪实践**：把知识内容与学习资料纳入检索，AI 基于个人知识带出处回答。
- **如何验证**：能解释 Embedding、相似度、检索、生成的协作关系；回答能追溯到个人知识来源。
- **产出**：个人知识检索能力。

### [Phase 10](phase-10/README.md) — Agent 与工具调用

- **学什么**：Tool Calling、工具定义与参数校验、Agent 工作流与状态、任务分解与结果验证、权限分级、确认机制、副作用控制、可观测性与失败恢复。
- **在哪实践**：AI 查询学习状态、制定计划，在用户确认后创建 / 更新任务。
- **如何验证**：能解释 Agent 与普通问答的区别；写操作无确认不执行、可审计可回滚。
- **产出**：权限明确的受控 Agent。

### [Phase 11](phase-11/README.md) — 测试与工程化

- **学什么**：单元 / 集成 / API / 前端 / E2E 测试、测试替身、AI 调用的测试策略、静态检查与格式化、Git 分支 / Review 工作流、缺陷与日志管理。
- **在哪实践**：为知识闭环、认证隔离、测评聚合、AI 边界、工具权限建立测试。
- **如何验证**：能说明各类测试的目的与取舍；核心流程回归可被自动发现。
- **产出**：有测试保护、可安全修改的代码库。

### [Phase 12](phase-12/README.md) — 容器化与部署运维

- **学什么**：镜像 / 容器 / Dockerfile / Compose、网络与卷、配置边界、Linux 文件 / 进程 / 权限 / 网络、Nginx 反向代理、DNS/HTTPS、发布 / 回滚 / 备份 / 监控、成本与维护责任。
- **在哪实践**：容器化全部服务并部署到云主机，通过域名 HTTPS 访问。
- **如何验证**：能讲清请求从域名到应用的路径，能独立完成一次发布与一次故障定位。
- **产出**：可访问、可更新、可诊断的线上 StudyOS。

## Phase 1 学习序列

当前唯一展开到细节的学习序列。严格按依赖推进，每一步都在产品功能中落地，不做脱离需求的练习：

```text
HTML（结构、表单）
  → CSS（布局、响应式、信息层级）
    → JavaScript（语法、对象、数组、函数）
      → DOM（查询、创建、更新、删除）
        → Event（监听、表单提交、用户交互）
          → 数据模型（Knowledge / Task / LearningRecord 分组结构）
            → State（数据 → UI 的渲染同步）
              → localStorage（JSON 序列化、读取、schema 版本）
                → 基础模块化（按职责拆 js 文件，不引入构建工具）
                  → 基础工程实践（手动验证清单、调试、错误处理）
                    → Git（提交节点、清晰提交信息）
```

与开发里程碑的一一对应关系见 [phase-01/README.md](phase-01/README.md#开发顺序里程碑level-2)。

## 能力地图（长期终点）

```text
Web 基础 → 前端工程 → HTTP/API → 后端工程 → 数据库 → 全栈应用
→ 测评与数据驱动 → AI 应用 → RAG → Agent → 质量工程 → 容器 → 部署运维 → 软件架构
```

最终目标：独立完成分析、设计、开发、调试、测试、部署与维护一个全栈 AI 应用的完整闭环。
