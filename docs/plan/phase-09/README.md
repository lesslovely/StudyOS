## 阶段定位

让 AI 回答问题时能够**基于 StudyOS 中用户自己的知识内容与学习资料**，并给出出处。Phase 8 的模型只看到当次上下文；本阶段建立“个人知识 → 可检索语料 → 检索增强生成”的完整链路。它是旧规划中“Knowledge Base / RAG”在知识核心模型下的重新落地：检索对象不是泛泛的资料堆，而是 Knowledge Node 内容与学习记录。

## 前置条件

- Phase 8 AI 服务层稳定（RAG 的生成环节依赖 LLM 能力）。
- 知识内容与资料有一定积累（自 P1 起持续录入），检索才有意义。
- 用户数据隔离与密钥管理已就绪。

## 目标矩阵

| 维度 | 内容 |
| --- | --- |
| 产品目标 | 基于个人知识的问答、带出处引用；发现已掌握内容与知识缺口；资料可纳入检索 |
| 用户价值 | “问我自己学过的东西”，答案可追溯到具体知识节点 / 资料，而非模型泛泛而谈 |
| 技术目标 | 文档切分与元数据、Embedding 与相似度、向量存储（pgvector 或独立向量库，届时选型）、检索 / 重排 / 上下文组装、RAG 评估（命中率、引用正确性） |
| 学习目标 | 见 [学习路线#Phase 9](../learning-roadmap.md) |

| 阶段产出 | 个人知识入库管道 + 带出处的检索问答能力 |

## 功能范围

**做什么**：

- 知识内容（定义、理解、示例、资料）切分、生成 embedding 并建立索引；知识更新时增量重建；
- 检索 + 重排 + 上下文组装，回答必须附引用（链接到具体知识节点）；
- 学习资料（Markdown / 文本）纳入检索，带归属与元数据；
- 缺口发现：结合掌握度指出“被问到但语料缺失 / 掌握薄弱”的知识；
- 权限：只检索当前用户的内容。

**不做什么**：Agent 工具调用（P10）、多模态检索、全网搜索接入、复杂知识图谱推理、过早优化大规模检索性能、锁定向量库厂商。

## 架构要点

- 向量索引与关系数据库**并存而非替代**：层级 / 关系 / 掌握度仍走关系库，语义检索走向量索引。
- 入库管道与业务写入解耦：知识变更触发索引更新（简单同步即可，不引入消息队列）。
- RAG 回答走 P8 的提案 / 依据展示机制：引用是强制输出，缺失引用的结论要标注不确定性。
- Embedding 模型与向量库选型进入阶段时按数据规模、成本、可运维性决定并记入 [decisions.md](../decisions.md)。

## 验证标准

- **功能验收**：资料能入库；对个人知识提问能返回相关片段与可点击出处；错误 / 缺失语料不编造。
- **技术验收**：切分、索引、增量更新、检索与上下文长度处理基本合理；调用失败可降级。
- **知识验收**：能讲清 Embedding、相似度、重排、生成各自的职责，以及 RAG 为什么仍会答错。
- **工程验收**：来源、权限、更新链路、成本可追踪；有一份小样本评估集与效果记录。

## 主要风险

- 切分粗糙导致检索失准——用小样本评估驱动调整，不凭感觉。
- 模型在无依据时编造——强制引用 + “无依据明说”的提示与校验。
- 提前上重型向量基础设施——优先选择与现有 PostgreSQL 共存的最简方案。
